1. 먼저 — 무엇이 어디서 도는가

가장 헷갈리기 쉬운 부분입니다. RosettaDrone 앱은 PC가 아니라 컨트롤러(RM500) 안에서 돕니다. RM500은 사실 안드로이드 태블릿이고, 우리가 만든 앱이 그 안에 설치되어 드론과 이야기합니다.

[ 오늘 한 일 — 앱을 만들어서 옮기기 (한 번이면 끝) ]

   내 PC  ────── USB 케이블 ──────▶  RM500
   (앱을 만든다)   파일을 옮길 뿐      (앱이 여기서 돈다)


[ 앞으로 매번 — 드론을 조종하고 관찰하기 ]

   내 PC                       RM500                    Mavic 2
 ┌──────────────┐          ┌──────────────┐          ┌────────┐
 │ QGroundControl│◀─ WiFi ─▶│ RosettaDrone │◀─ DJI ──▶│  기체  │
 │  파이썬 코드  │  UDP     │     앱       │  전용전파 │        │
 └──────────────┘  14550   └──────────────┘ (OcuSync) └────────┘
        └── 같은 WiFi에 붙은 두 기기 ──┘      └ WiFi와 무관한 별도 무선 ┘
💡

PC의 역할이 두 개입니다.

① 앱 공장 — 소스코드로 앱을 만든다. 오늘 끝났고 다시 안 해도 됩니다.
② 지상국 — 드론에게 명령을 넣고 상태를 받아본다. 비행할 때마다 필요합니다. 연구의 본체가 여기입니다.

2. 용어 사전 — 헷갈리는 것부터

🛰️ 통신 — 드론과 이야기하는 방법
MAVLink마브링크
드론 업계의 표준 공용어. "여기로 가라", "지금 배터리 몇 %야" 같은 말을 정해진 형식으로 주고받습니다. 공개 규격이라 누구나 쓸 수 있습니다. DJI는 이 말을 못 합니다. 그래서 RosettaDrone이 통역사 노릇을 합니다 — 이 프로젝트의 존재 이유입니다.
UDPUser Datagram Protocol
네트워크로 데이터를 보내는 방식. 편지를 그냥 던지고 도착 확인은 안 합니다. 그래서 빠르지만 가끔 유실됩니다. 엽서에 비유됩니다. 반대로 TCP는 등기우편(도착 확인·재전송)입니다. 드론 상태는 1초에 여러 번 오므로 하나쯤 잃어도 되고, 느린 것이 더 나쁩니다 — 그래서 UDP를 씁니다.
포트14550 / 5600
한 컴퓨터 안의 방 번호. IP주소가 건물 주소라면 포트는 몇 호실인지입니다. 14550 = MAVLink 표준 방(위치·자세·배터리). 5600 = 영상이 오는 방. QGC는 14550을 자동으로 엿듣고 있습니다.
QGCQGroundControl
PC에서 도는 드론 관제 화면 소프트웨어. 지도 위에 드론 위치를 그리고, 배터리·고도·자세를 보여주고, 미션(경유지)을 올릴 수 있습니다. 오픈소스 표준 도구입니다. "드론용 관제탑 화면"이라고 보시면 됩니다. 여기에 드론이 뜨면 = 오늘의 진짜 성공입니다.
지상국 / GCSGround Control Station
드론을 지상에서 감시·조종하는 쪽 전체를 부르는 말. QGC가 그 대표적인 프로그램입니다. 앱 설정의 "Use GCS on an external device"는 "관제 화면이 이 컨트롤러 말고 딴 기기(=내 PC)에 있다"는 뜻입니다. 이걸 안 켜면 앱이 자기 자신에게만 데이터를 보냅니다.
OcuSync오큐싱크
DJI 고유의 컨트롤러↔기체 무선. 암호화되어 있고 우리가 건드릴 수 없습니다. WiFi와 완전히 별개의 전파라서, PC와 통신하려고 WiFi를 써도 드론 조종 링크를 방해하지 않습니다. 이 분리 덕에 우리 구조가 성립합니다.
🔧 앱 만들기 — 오늘 PC에서 한 일
APKapp-debug.apk
안드로이드 앱 설치 파일. 윈도우의 .exe에 해당합니다. 오늘 만든 것이 이겁니다(188MB).
빌드 / Gradle그레이들
소스코드 → 앱으로 조립하는 과정과, 그 조립을 지휘하는 도구. 재료(코드)와 레시피(설정)를 넣으면 완성품(APK)이 나오는 공장 라인입니다. 노션 계획서가 "가장 오래 걸리고 실패가 흔한 구간"이라고 한 곳인데, 2분 7초 만에 첫 시도로 통과했습니다.
JDK / Java자바
안드로이드 앱이 쓰는 프로그래밍 언어와 그 실행 환경. ⚠ 오늘 가장 큰 함정이 여기 있었습니다. 이 프로젝트는 2020년경 도구라 Java 11이 필요한데 PC에는 21밖에 없었습니다. 그냥 돌리면 첫 줄에서 죽습니다. 그렇다고 21을 지우면 안 되는 게, 앱 부품을 받는 다른 도구는 17 이상을 요구합니다. → 둘을 같이 두고 용도별로 갈라 썼습니다.
Android SDK / NDK
앱을 만들 때 필요한 부품·연장 상자. 버전이 여러 개인데 이 프로젝트가 지정한 정확한 버전만 받았습니다(최신을 쓰면 깨집니다).
git / clone
소스코드 저장소에서 코드 한 벌을 통째로 받아오는 것. 인터넷의 코드 창고에서 우리 PC로 복사한 것입니다.
git-lfsLarge File Storage
git이 큰 바이너리 파일(영상 코덱 같은)을 따로 관리하는 확장. ⚠ 이게 없으면 큰 파일이 "진짜 파일은 저기 있음"이라 적힌 쪽지 130바이트로만 받아집니다. 빌드는 되는데 앱이 실행 즉시 죽습니다 — 증상이 원인을 안 가리켜 찾기 어려운 종류라, 오늘 실물 크기(7MB)를 눈으로 확인했습니다.
adbAndroid Debug Bridge
PC에서 USB로 연결된 안드로이드 기기를 조작하는 도구. 앱 설치, 로그 읽기 등을 합니다. RM500에 앱을 넣을 때 쓸 명령이 adb install 입니다.
App KeyDJI 앱 인증키
DJI가 발급한 "이 앱은 드론을 만져도 된다"는 허가증. 앱을 켜면 DJI 서버에 이 키를 확인받습니다. 그 확인 결과가 DJI 표시등 색으로 나옵니다. 이게 오늘의 최종 관문입니다.

5.5단계를 왜 따로 했나 — 실패의 원인을 미리 갈라놓기 위해서입니다.

이따 기체에서 라이트가 빨간색으로 뜨면 원인이 셋일 수 있습니다: ① 앱을 잘못 만들었다 ② 앱 이름표를 잘못 붙였다 ③ DJI가 이 방식을 막았다. ③이면 프로젝트 방향을 바꿔야 하는 중대한 판정인데, ①·②와 섞이면 엉뚱하게 포기하게 됩니다.

그래서 기체를 켜기 전에 ①·②를 미리 지웠습니다 — APK 안을 뜯어서 앱 이름표가 DJI에 등록한 것과 정확히 같은지, 인증키가 실제로 박혔는지, 부품이 다 들어갔는지를 확인했습니다. 전부 정상이었습니다.

→ 이제 라이트가 빨갛다면 그건 오직 ③입니다. 판정이 깨끗해졌습니다.

4. 아침에 미리 잡아 둔 함정 셋

전부 "조용히 실패해서 원인 찾기 어려운" 종류입니다. 기체 앞에서 만났으면 시간을 많이 썼을 것들입니다.

🧱

① 방화벽(ufw)이 켜져 있습니다 — 아직 해결 안 됨, 박사님 조치 필요

PC가 RM500이 보내는 데이터를 말없이 버립니다. 앱 쪽은 정상으로 보이는데 QGC만 텅 비는, 가장 헷갈리는 증상입니다.

sudo ufw allow 14550/udp comment 'MAVLink RosettaDrone'
sudo ufw allow 5600/udp  comment 'RosettaDrone video'
📶

② PC와 RM500이 같은 네트워크에 있어야 합니다 — 방법 결정됨

PC는 유선만 쓰고 있고, WiFi로 주변을 훑으니 네트워크가 딱 하나(휴대폰 핫스팟)만 잡혔습니다. WiFi 7 카드인데 이 정도면 본체 뒤 안테나가 안 꽂혀 있을 가능성이 높습니다.

결정: ① RM500 USB 테더링을 먼저 시도(케이블 하나로 끝나고 신호 문제가 사라짐) → 안 되면 ② 휴대폰 핫스팟.

📦

③ QGC가 이 PC에서 그냥은 안 켜집니다 — 해결 완료

QGC는 AppImage라는 형식인데 이 PC에 libfuse2라는 부품이 없어 실행이 안 됩니다. 관리자 권한 없이 미리 압축을 풀어 바로 실행 가능한 상태로 만들어 뒀습니다.

추가로 만든 것 — 진단 도구

"QGC에 아무것도 안 뜬다"는 증상은 원인이 셋인데 화면만 봐서는 구별이 안 됩니다. 그래서 QGC 없이 데이터가 오기는 하는지만 보는 작은 프로그램을 만들었습니다(udp_probe.py).

원인진단 도구에서구별법
앱이 안 보낸다아무것도 안 옴앱 화면의 GCS 표시등도 꺼져 있음
방화벽·네트워크가 막는다아무것도 안 옴앱은 보내는데 도착을 안 함
QGC 설정 문제데이터가 보임← 이걸로 분리됩니다

즉 이 도구에 데이터가 보이면 배관은 살아 있고 문제는 QGC 쪽이라는 뜻입니다.

⚠ 함정 ① — 시계가 틀리면 register failed 로 나타난다

🕐

증상: 앱이 register failed → check network setting. 그런데 브라우저로 구글은 열림.

진짜 원인: 브라우저에 date of certificate is invalid 가 떴습니다. RM500의 날짜가 틀려 HTTPS 인증서 검증이 전부 실패하고 있었습니다. HTTPS는 인증서 유효기간을 기기 시계와 대조하기 때문입니다. 브라우저는 경고를 넘길 수 있지만 앱은 못 넘깁니다 — DJI SDK는 그냥 실패하고 그걸 "네트워크를 확인하라"로 표시합니다.

해결: 설정 → 시스템 → 날짜 및 시간 → 자동 (또는 수동 + 시간대 서울/GMT+9). 확인은 브라우저에서 HTTPS 사이트가 경고 없이 뜨는지로 합니다.

하마터면 "DJI가 v4를 막았다"고 잘못 결론 내릴 뻔했습니다. 증상이 원인을 전혀 안 가리켰습니다.

⚠ 함정 ② — 저장소 권한이 없으면 기체 연결 순간 크래시

앱이 /sdcard/DroneApp/ 에 로그를 씁니다(DroneModel.java:211). 첫 실행 때 물어본 건 위치·전화뿐이라 저장소가 빠져 있었습니다. 해결: 설정 → 앱 → RosettaDrone → 권한 → 전부 허용.

⚠ 함정 ③ — 테스트 모드는 프로세스를 죽여야 빠져나온다

🎭

증상: START를 눌러 초록불 + Mavic 2 가 떴는데도 텔레메트리는 계속 가짜. 좌표가 -32.854074, -71.215363(칠레)로 고정.

// DummyProduct.java — 테스트 모드가 쓰는 가짜 기체
private double homeLat = -32.8540743;   // 우리가 받은 값과 정확히 일치
private double homeLng = -71.2153629;
private float  alt = 0;                  // 고도 0
private boolean isFlying = false;        // 속도 0

// RDApplication.java:19
public static boolean isTestMode = false;   // static — 프로세스가 사는 한 유지

// DroneModel.java:278
m_aircraft = (Aircraft) RDApplication.getProductOrDummy();   // 한 번 잡아 필드에 보관

기체 참조를 캐시하므로 START로 모드를 바꿔도 이미 잡아 둔 가짜 참조는 안 바뀝니다. 그리고 최근 앱에서 밀어 없애는 것으로는 안드로이드 프로세스가 안 죽습니다.

해결: 설정 → 앱 → RosettaDrone → 강제 중지 → 다시 열고 START.

시작 화면 버튼은 셋입니다 — 시뮬레이터 · START(진짜 기체) · TEST(가짜). 기체가 안 붙어 있으면 앞의 둘이 비활성이라 TEST만 눌리는 것처럼 보입니다.

6. Google Play 서비스 경고 — 조사 결과

경고: "Rosetta Drone won't run without Google Play services, which are not supported by your device" RM500은 중국 내수 계열 안드로이드라 GMS가 없는 것이 정상입니다.

✅

판정: 오늘 증상의 원인이 아닙니다. 지도 표시만 못 하게 합니다.

확인결과
앱이 Play 서비스를 직접 검사하나안 합니다. GoogleApiAvailability 가 소스에 한 군데도 없습니다 → 경고는 Maps SDK가 스스로 띄우는 것
위치를 Play 서비스로 받나아닙니다. 표준 안드로이드 LocationManager 를 씁니다
기체 연결 경로가 걸리나아닙니다. registerApp() → SDK 콜백. 지도와 무관
지도가 없을 때 자동 경로가 터지나안 터집니다. updateDroneLocation() 에 if (aMap != null) 가드가 있습니다
DJI MSDK v4가 요구하나아닙니다. 중국 시장용 설계. RM500 자체가 GMS 없이 DJI 앱을 돌립니다
결정적 반증그 경고가 뜬 채로 인증이 통과했고 초록불 + Mavic 2 가 떴습니다

덧붙여 우리는 구글 지도 키를 일부러 임시값으로 넣었습니다. Play 서비스가 있었어도 지도는 어차피 안 떴습니다 — 지도 실패는 예정된 일이고 오늘 증상과 별개입니다.

💣

다만 하나 — markWaypoint() 에는 가드가 없습니다. 나중에 터질 지뢰입니다.

// MainActivity.java:503  markWaypoint()
m_line.add(aMap.addPolyline(...));            // 511행 — null 검사 없음
gotoMarker = aMap.addMarker(markerOptions);   // 528행 — 없음

지도가 초기화되지 않은 이 기기에서 웨이포인트를 찍는 순간 NullPointerException으로 죽습니다. 우리 연구 파이프라인이 바로 waypoint 방식이라, DroneKit으로 미션을 넣기 시작하면 걸립니다. (README의 "이륙 후 GOTO를 누르면 에러 상태에 빠진다" 도 같은 뿌리일 수 있습니다.)

→ 두 줄에 null 가드를 넣고 재빌드하면 됩니다(2분). 미리 할지는 정하시면 됩니다.

"START/SIM에서 연결이 끊긴다" — 화면을 믿지 마세요

// ConnectionActivity.java
mBtnOpen.setEnabled(productConnected);   // 290행  START
mBtnSim .setEnabled(productConnected);   // 291행  SIMULATOR

START·SIM은 기체가 붙어 있을 때만 활성, TEST는 항상 활성입니다. → 테스트만 되는 것처럼 보이는 건 기체 링크가 붙었다 끊겼다 하기 때문입니다.

그리고 앱에 표시 버그가 있습니다:

if (RC 연결) { mStatusBig.setText("RC connected"); }   // 281행
mStatusBig.setText(R.string.connection_loose);          // 286행 — 조건 밖! 방금 쓴 걸 덮어씀

RC가 정상이어도 기체만 안 붙으면 항상 connection loose 로 보입니다.
