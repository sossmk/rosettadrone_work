되돌아오는 길은 link_node 가 앱 텔레메트리를 풀어 내는 /gcs/daiv/rd/fix(위치, 약 5Hz)와 /gcs/daiv/rd/heading(기수, 약 10Hz)이다. nav_node 는 위치 루프만 담당하고, 바람을 이기며 실제로 그 속도를 내는 속도 루프는 DJI 비행제어기 안에 있다. 두 루프가 겹겹이 있다는 것이 뒤의 한계 논의에서 중요하다.

tick() 한 번에 일어나는 네 단계

예시는 9/15 실기 조건: 위도 37.5°, 기수 180°(남향), 목표는 북쪽 5 m.

① 거리

구면 위 두 점의 대원 거리. mav.meters_between 은 haversine 공식이다. 수십 m 에서는 평면 근사와 mm 단위로 같지만, 극 근처나 먼 거리에서도 틀리지 않는다.

a = sin²(Δφ/2) + cos φ₁ · cos φ₂ · sin²(Δλ/2) d = 2R · asin(√a) R = 6 371 000 m

위도 1° ≈ 111 195 m. 북 5 m 는 Δφ = 0.0000450°. 경도 1° 는 cos 37.5° 만큼 짧아서 88 216 m이다.

② 방위

현재 위치에서 목표를 볼 때의 방위각(북=0°, 시계방향). mav.bearing_between 은 대원 항로의 출발 방위(initial bearing)다. 매 tick 새로 계산하므로 계속 목표를 다시 조준하는 셈이다.

θ = atan2( sin Δλ · cos φ₂ , cos φ₁ · sin φ₂ − sin φ₁ · cos φ₂ · cos Δλ ) → 0~360°

북쪽 목표 → θ = 0°

③ 상대각

지구 기준 방위를 기체 기준으로 바꾼다. 0=앞, +90=오른쪽, ±180=뒤. +540 은 음수 나머지를 피하려고 360 을 한 번 더 더한 것이다.

rel = (θ − heading + 540) mod 360 − 180

(0 − 180 + 540) mod 360 − 180 = 180° → 뒤

④ 속도

속력은 거리에 비례하고 상한에서 자른다. 방향은 rel 로 앞·오른쪽 성분으로 나눈다. 고도는 따로 같은 모양의 P 제어다.

speed = min(max_speed, kp · d) kp = 0.35 /s vx = speed · cos(rel) 앞 + vy = speed · sin(rel) 오른쪽 + vz = clamp(kp_alt · (고도목표 − 고도), ±max_vz)

d = 5 m, max_speed 1.0 → speed = min(1.0, 1.75) = 1.0 → vx = −1.00, vy = 0.00 (뒤로 1 m/s)

9/15 에 "x:−5 가 전진" 이었던 이유

그날 goal_offset 은 지구 기준(x=북, y=동) 이었다. 기수가 남쪽이면 남(x=−5)이 기체의 앞이고, 서(y=−5)가 기체의 오른쪽이다. 네 단계 계산은 맞았고, 규약이 현장 감각과 달랐다. 그래서 goal_offset 을 기체 기준으로 바꿨다(아래 회전 참고).

속도 프로파일: 등속 구간과 감속 구간

min(max_speed, kp·d) 는 거리 축에서 꺾인 직선이다. 꺾이는 거리 d* = max_speed / kp 보다 멀면 상한 속도로 가고, 안쪽에서는 속도가 거리에 비례한다. 비례 구간에서는 ḋ = −kp·d 이므로 거리가 지수적으로 준다(시상수 1/kp ≈ 2.86 s).

걸리는 시간은 두 구간을 더하면 된다. 등속 구간은 (d₀ − d*) / max_speed, 감속 구간은 ln(d* / r) / kp 이다(r = arrive_radius). 기본값으로 20 m 목표면 (20 − 7.14)/2.5 + ln(7.14)/0.35 ≈ 5.1 + 5.6 = 10.7 s.

goal_offset: 기체 기준 → 북·동 회전

9/15 이후 /gcs/daiv/nav/goal_offset 의 x 는 앞, y 는 오른쪽이다. 받는 순간의 기수 h 로 한 번 돌려 북·동 m 로 만들고, 그것을 위경도 차이로 바꿔 고정된 목표 좌표를 만든다. 비행 중에 기수가 돌아도 목표는 움직이지 않는다.

북 = x · cos h − y · sin h 동 = x · sin h + y · cos h Δlat = 북 / R (rad) Δlon = 동 / (R · cos lat) (rad)
기수 h입력북동의미
0°{x: 5}+50북향의 앞 = 북
180°{x: 5}−50남향의 앞 = 남
180°{y: 5}0−5남향의 오른쪽 = 서
90°{y: 5}−50동향의 오른쪽 = 남

이 회전은 ③ 상대각의 역변환이다. ③은 지구 → 기체, 여기서는 기체 → 지구. 그래서 목표를 준 직후 첫 tick 의 rel 은 atan2(y, x) 와 같다.

파라미터 5개가 조절 손잡이 전부다. 타이머 0.05 s = 20 Hz. 위치는 5 Hz 로 오므로 같은 위치로 약 4번 같은 명령을 낸다. 해롭지는 않고, link_node 데드맨(0.3 s)을 채우는 역할이다.

on_fix / on_hdg

최신 값만 저장한다. 필터링은 없다. t_pos 는 신선도 게이트용이다.

on_offset

기체 기준 → 북·동 → 위경도. 평면 근사지만 수백 m 까지 오차는 무시할 만하다.

start

목표를 덮어쓰기만 한다. 비행 중에 새 목표를 주면 그 자리에서 방향을 튼다. CSV 는 목표마다 새 파일이다.

stop

0 을 한 번만 낸다. 계속 내면 link_node 가 ACTIVE 로 남아 Virtual Stick 이 풀리지 않는다(할일.md 제약 #21).

tick — 게이트

좌표가 1 s 넘게 안 오면 멈춘다. link_node 가 새 값만 발행하기 때문에 이 게이트가 의미를 가진다.

tick — 도착

수평 거리와 고도 오차가 둘 다 arrive_radius 안이면 끝. 한 번만 들어와도 끝이다(앱은 7번 연속).

tick — P 제어

위 네 단계 그대로다. 수평 속력은 벡터 크기로 자르므로 대각선에서도 max_speed 를 넘지 않는다.

def meters_between(lat1, lon1, lat2, lon2):    """두 좌표 사이 거리 (m). 짧은 거리라 구면 근사로 충분하다."""    R = 6371000.0    p1, p2 = math.radians(lat1), math.radians(lat2)    dp = math.radians(lat2 - lat1)    dl = math.radians(lon2 - lon1)    a = math.sin(dp / 2) ** 2 + math.cos(p1) * math.cos(p2) * math.sin(dl / 2) ** 2    return 2 * R * math.asin(min(1.0, math.sqrt(a)))
def bearing_between(lat1, lon1, lat2, lon2):    """lat1,lon1 에서 lat2,lon2 를 본 방위각 (0~360°, 북=0, 동=90)."""    p1, p2 = math.radians(lat1), math.radians(lat2)    dl = math.radians(lon2 - lon1)    y = math.sin(dl) * math.cos(p2)    x = math.cos(p1) * math.sin(p2) - math.sin(p1) * math.cos(p2) * math.cos(dl)    return math.degrees(math.atan2(y, x)) % 360.0
def relative_bearing(move_bearing, heading):    """이동 방위각을 기수 기준 상대각(-180~180)으로. 0=앞, +90=오른쪽, 180=뒤, -90=왼쪽."""    return (move_bearing - heading + 540.0) % 360.0 - 180.0

한계, 그리고 LOS 는 언제 필요한가

바람

위치 루프에 I 항이 없으면 보통은 정상상태 오차가 남는다. 하지만 여기서는 DJI 속도 루프가 GPS 대지속도를 맞추며 바람을 보상한다. 그래서 "0 m/s" 명령이면 제자리에 선다. 오차는 속도 루프가 못 따라가는 과도 구간과 GPS 흔들림(1~2 m) 정도다. 9/15 에 정확도가 좋았던 이유다.

경로

매 tick "지금 위치 → 목표" 를 다시 조준한다. 옆으로 밀리면 원래 직선으로 돌아가지 않고 새 위치에서 목표로 곧장 간다. 점 하나로 가는 데는 문제가 없지만, 출발점과 목표를 잇는 선을 지켜야 할 때(좁은 통로, 웨이포인트 연속, 측량 라인)는 경로가 휜다.

타력

SIM 실측으로 멈춘 뒤 0.6~0.8 m 더 간다. 하지만 그건 빠를 때 이야기다. 비례 구간 끝에서는 0.35 m/s 까지 줄어든 뒤 멈추므로 밀림이 작다. max_speed 를 올리면 등속 구간이 길어질 뿐 도착 속도는 같다.

LOS

Line-of-Sight 유도는 출발점 A 와 목표 B 를 잇는 직선을 기준으로 한다. 선 위의 진행 거리 s 와 선에서 벗어난 거리 e(cross-track)를 구하고, 선 앞쪽 Δ(lookahead) 지점을 겨눈다.

χ_cmd = χ_path + atan(−e / Δ) Δ 가 작을수록 선으로 급하게 복귀

선박·고정익처럼 옆으로 못 가는 기체에서는 방향각 하나로 이걸 해야 한다. 멀티콥터는 옆으로도 갈 수 있으므로 더 간단하게 쓸 수 있다.

v_along = min(vmax, kp · (L − s)) 선을 따라 v_cross = −k_e · e 선으로 복귀

필요한 때: 웨이포인트를 여러 개 이을 때, 경로 자체가 임무일 때. 불필요한 때: 점 하나로 가기, 태그 위 호버·정밀 착륙(F·G). 이 경우 목표가 계속 움직이는 점이라 지금의 P 제어가 맞는 모양이다.

연습 문제

손으로 풀고 펼쳐서 확인. 마지막 둘은 노트북의 실측 CSV 로 한다.

1. 기수 90°(동향)에서 {x: 3, y: 4} 를 주면 목표는 북·동으로 몇 m 인가?

풀이

북 = 3·cos90 − 4·sin90 = −4, 동 = 3·sin90 + 4·cos90 = +3. 남 4 m, 동 3 m. 동향의 앞 3 m 는 동, 오른쪽 4 m 는 남이므로 맞다.

2. 목표 방위 10°, 기수 350° 이다. rel 과 사람 말 방향은?

풀이

(10 − 350 + 540) mod 360 − 180 = 200 − 180 = +20° → name_direction 은 앞(±22.5° 안). 단순히 10 − 350 = −340 으로 하면 틀린다. +540 트릭이 이 경계를 처리한다.

3. 거리 4 m, rel = 120°, 기본 파라미터에서 vx·vy 는?

풀이

speed = min(2.5, 0.35·4) = 1.4. vx = 1.4·cos120 = −0.70, vy = 1.4·sin120 = +1.21. 뒤-오른쪽.

4. max_speed:=1.0 으로 10 m 목표를 주면 도착까지 대략 몇 초인가? (지연·가속 무시)

풀이

d* = 1.0/0.35 = 2.86 m. 등속 (10 − 2.86)/1.0 = 7.1 s, 감속 ln(2.86/1)/0.35 = 3.0 s → 약 10 s. 실제 CSV 와 비교하면 지연과 가속 한계가 보인다.

5. 실측 CSV 에서 거리와 명령 속력을 뽑아, 비례 구간에서 속력/거리 ≈ 0.35 인지 확인하라.

명령
f=$(ls -t ~/drone_ws/navlog/*.csv | head -1) awk -F, 'NR>1 && NR%20==2 {s=sqrt($7^2+$8^2); printf "%6.1fs d=%5.2f v=%4.2f v/d=%4.2f\n", $1-t0, $6, s, ($6>0?s/$6:0)} NR==2{t0=$1}' "$f"

1초 간격으로 한 줄. 멀 때는 v 가 max_speed 로 붙어 있고, 가까워지면 v/d 가 0.35 로 모인다. d 가 계단처럼 변하면 5 Hz 위치 갱신이 보이는 것이다.

6. 같은 CSV 에서 hdg 칸이 9/15 goal_offset 시험 동안 180 근처였는지 확인하라.

명령
awk -F, 'NR>1 {print FILENAME, $5}' ~/drone_ws/navlog/20260915-*.csv | sort -u -k1,1
