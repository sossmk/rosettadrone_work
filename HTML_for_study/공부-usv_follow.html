USV 좌표 하나가 기수·틸트·속도가 되기까지

USV 가 보낸 위경도·헤딩과 우리 위치·기수·고도만으로, 영상 없이 카메라를 USV 에 겨누고 대형 자리를 지킨다. 핵심은 나와 USV 를 잇는 시선 벡터 하나를 좌우 각(방위)과 위아래 각(틸트)으로 나누는 것이다. 자리 지키기는 nav_node 와 같은 P 제어에 USV 속도를 더한 것이다.

흐름시선 벡터좌표계여섯 단계feedforward기수틸트화면에서가정과 오차코드연습 문제

되돌아오는 길은 link_node 가 내는 /rd/fix(위경도 + 상대고도, 약 5Hz)와 /rd/heading(기수, 약 10Hz)이다. 이 노드는 카메라가 무엇을 보는지 모른다. 태그 추종과 달리 영상을 쓰지 않고, 두 좌표만으로 "카메라가 어디를 봐야 하는가"를 계산해 그쪽으로 돌려 놓는다. 되먹임 없는 개루프 겨눔이다.

뜨자마자 움직이지 않는다. /usv/follow true(rd_cmd.py usv 의 space)를 받아야 시작한다. publish:=false 로 띄우면 /cmd_vel 은 내지 않고 짐벌만 겨눈다. 지상에서 겨눔만 볼 때 쓴다. move:=false 는 수평·수직만 막고 기수는 살려 둔다(제자리 회전+틸트), aim:=false 는 짐벌만 막는다. 셋 다 출력 스위치일 뿐 계산은 갈라지지 않는다 — 능력을 하나씩 떼어 평가하려고 둔 것이다.

핵심 한 장: 시선 벡터를 두 각으로 나눈다

카메라가 USV 를 보려면 두 각을 맞춰야 한다. 좌우(방위)와 위아래(틸트)다. 둘 다 나에서 USV 로 가는 벡터 하나에서 나온다. USV 는 수면 위에 있고, 우리는 수면에서 h 만큼 떠 있다고 본다.

식의 이름은 코드와 맞췄다. me = 우리 위치, est = p̂(추정한 USV 위치), goal = 대형 목표점.

L = (ΔN, ΔE, −h) 시선 벡터 me → est. h = 우리 상대고도 s = √(ΔN² + ΔE²) 수평거리 — mav.meters_between(me, est) β = atan2(ΔE, ΔN) 방위 — mav.bearing_between(me, est) e = wrap(β − ψ) 좌우 오차 → 몸체를 돌려 0 으로 (ψ = 우리 기수) θ = −atan2(h, s) 틸트 → 짐벌 채널 9 로 (0 = 수평, −90 = 바로 아래)

좌우는 짐벌이 아니라 몸체로 맞춘다. 짐벌 yaw(채널 8)는 앱이 기억한 직전 값과의 차이만큼 도는 상대·누적각이다. 명령 한 발을 잃으면 기준이 어긋나고, 부호도 실기로 확인하지 않았다. 위아래는 짐벌 pitch(채널 9)가 절대각이라 계산한 θ 를 그대로 보내면 된다.

USV 가 보낸 좌표 p 를 그대로 쓰지 않고, 지연을 메우려고 앞으로 민 p̂ 를 쓴다. 다음 절의 ② 가 그 계산이다.

tick() 한 번에 일어나는 여섯 단계

예시 숫자는 plan() 을 실제로 돌린 값이다. 우리는 원점, 고도 8 m, 기수 0°(북). USV 는 북 3 m · 동 12 m 에서 헤딩 90°(동)이고, 2초 동안 동쪽으로 2 m 움직였다. 마지막 좌표는 0.3 초 전에 받았다. 대형은 (−10, 0, 10), 곧 USV 뒤 10 m · 고도 10 m (기본값이 아니라 예시 값이다).

① 속도 추정

usv_velocity(). 최근 vel_window(2 s) 안에 받은 좌표 가운데 맨 앞과 맨 뒤 두 점만 쓴다. 두 점 사이가 0.5 s 보다 짧으면 0 이다.

d = meters_between(p0, p1) b = bearing_between(p0, p1) vn = d · cos(b) / (t1 − t0) ve = d · sin(b) / (t1 − t0)

2 s 동안 동쪽 2 m → d = 2, b = 90° → (vn, ve) = (0.00, 1.00) m/s

창이 길면 GPS 흔들림이 덜 들어가고, 짧으면 USV 가 방향을 바꾼 것을 빨리 안다. 좌표의 짧은 시간 흔들림을 σ 라 하면 속도 잡음은 대략 √2·σ / T 다. σ = 0.3 m, T = 2 s 면 0.21 m/s.

② 외삽

plan() 58행. 마지막 좌표는 이미 age 초 묵었다. 여기에 lead_secs 를 더한 τ 만큼 등속으로 민다. offset_to_gps 에 기수 0 을 주면 "앞 = 북, 오른쪽 = 동" 이 되므로, 속도 × τ 를 그대로 북·동 이동으로 넣을 수 있다.

τ = age + lead_secs lead_secs = 0.5 s est = p + (vn·τ, ve·τ) = offset_to_gps(p, 0°, vn·τ, ve·τ)

τ = 0.3 + 0.5 = 0.8 s → p̂ = (북 3.0, 동 12.8)

③ 대형 → 목표점

plan() 59행. 대형 (f, r) 은 USV 헤딩 기준이다. nav_node 의 goal_offset 과 같은 회전인데, 우리 기수 대신 USV 헤딩 ψu 로 돌린다. 그래서 USV 가 돌면 목표점도 같이 돈다.

N = f · cos ψu − r · sin ψu E = f · sin ψu + r · cos ψu goal = est + (N, E)

(f, r) = (−10, 0), ψu = 90° → N = 0, E = −10 → 목표점 = (북 3.0, 동 2.8). 동쪽을 보는 USV 의 "뒤" 는 서쪽이다.

④ 병진

plan() 61–70행. nav_node 와 같은 P 제어로 목표점까지 가는 속도를 만든다. 여기에 USV 속도를 우리 기체축으로 돌려 더하고(feedforward), 합친 크기를 max_speed 로 자른다.

d = meters_between(me, goal) rel = wrap(bearing(me, goal) − ψ) speed = min(max_speed, kp · d) kp = 0.35 /s vx = speed·cos(rel) + ( vn·cos ψ + ve·sin ψ) # 앞 vy = speed·sin(rel) + (−vn·sin ψ + ve·cos ψ) # 오른쪽 vz = clamp(kp_alt · (a − h), ±max_vz) # a = 대형 고도 |(vx, vy)| > max_speed (2.5 m/s) 이면 같은 비율로 줄인다

d = 4.10 m, 방위 43.0° → speed = 0.35 × 4.10 = 1.44 → P = (1.05, 0.98), ff = (0.00, 1.00) → (vx, vy) = (1.05, 1.98), 크기 2.24 < 2.5 라 안 자른다. vz = 0.35 × (10 − 8) = 0.70

⑤ 기수

plan() 72–73행. 몸체를 목표점이 아니라 p̂(USV) 쪽으로 돌린다. 가는 방향과 보는 방향은 다를 수 있다.

e = wrap(bearing(me, est) − ψ) wz = clamp(kp_yaw · e, ±max_yaw_rate) # kp_yaw 0.8 /s, max 30°/s → rad/s 로 바꿔 /cmd_vel 의 angular.z 로

bearing(me, est) = 76.8° → e = 76.8° → 0.8 × 76.8 = 61.4 → 30°/s 로 자름 (0.524 rad/s)

⑥ 틸트

plan() 75–76행에서 계산하고 aim() 이 보낸다.

s = meters_between(me, est) θ = clamp(−atan2(max(h, 0), s), −90, 0) PWM = 1500 + 5.5 · θ → DO_SET_SERVO(183), 채널 9 보내는 조건: aim 켜짐 · 직전 전송에서 0.5 s 지남 · |θ − 직전 θ| ≥ 2°

s = 13.15 m, h = 8 → θ = −31.3° → PWM 1327.7

같은 화살표, 다른 기체축 숫자

같은 순간 우리 기수가 60° 였다면 P = (1.37, −0.42), ff = (0.87, 0.50), 합 (2.24, 0.08) 이다. 숫자는 달라도 지구 기준으로는 크기 2.24 의 같은 화살표다. 매 tick 지금 기수로 다시 나누므로, 몸체가 USV 쪽으로 도는 동안에도 가는 방향은 흔들리지 않는다. 이때 e = 16.8° → wz = 13.4°/s.

feedforward 는 왜 있나

P 만 있으면 속도 명령이 거리에 비례한다. USV 가 v 로 계속 가면, 우리가 v 로 따라가려면 목표점에서 v/kp 만큼 떨어져 있어야 한다. 그 거리만큼 늘 뒤처진다. USV 속도를 미리 더해 두면(feedforward) P 는 남은 오차만 맡는다.

kp · e = v → e = v / kp P 만 쓸 때 늘 이만큼 뒤처진다 e → 0 feedforward 를 더하면 (속도 추정이 맞고 max_speed 에 안 걸릴 때)
USV 속도P 만 (kp 0.35)P + feedforward
0.5 m/s1.43 m 뒤0
1.0 m/s2.86 m 뒤0
2.0 m/s5.71 m 뒤0 — 다만 feedforward 가 2.0 을 쓰고 교정에는 0.5 만 남는다
3.0 m/s못 따라간다못 따라간다 — max_speed 와 link_node 캡이 둘 다 2.5

feedforward 의 정확도는 ① 속도 추정에 달렸다. 속도를 20% 작게 잡으면 남는 오차는 0.2·v/kp, 1 m/s 에서 0.57 m 다.

기수: 몸체로 겨눈다

  • 시상수. 잘리지 않는 범위에서 e 는 e·exp(−kp_yaw·t) 로 줄고, 시상수는 1/kp_yaw = 1.25 s 다. 오차가 37.5° 를 넘으면 30°/s 로 잘린다. 예시의 76.8° 가 화면 가장자리(32°) 안으로 들어오기까지 약 1.5 s 걸린다.
  • 캡이 두 겹이다. 노드의 max_yaw_rate 30°/s 가 먼저 걸리고, link_node 의 75°/s 는 안전망이다.
  • 옆으로 날 수 있다. 대형 1(왼쪽 10 m)면 USV 와 나란히 가면서 몸체는 오른쪽(USV)을 본다. #84 가 기체 기준 속도라서 가능하다.
  • 좌우 오차는 영상으로 확인하지 않는다. 계산상 e 가 0 이어도, 우리 기수 센서나 USV 좌표가 틀린 만큼 화면에서 옆으로 밀린다(화면에서).

실기에서 확인할 것 — 짐벌은 2초에 걸쳐 돈다

앱은 DO_SET_SERVO 를 받을 때마다 Rotation.Builder().time(2) 로 2초에 걸쳐 짐벌을 돌린다. 그런데 aim() 은 최대 0.5 초마다 새 각을 보낸다. 9/16 gimbal_test 는 1초 만에 다음 명령을 보내 회전을 덮어썼고, 짐벌이 움찔하기만 해서 "안 움직였다"로 보였다. USV 가 움직여 틸트가 2° 넘게 계속 바뀌면 같은 일이 생길 수 있다.

dry-run 은 PWM 을 보냈는지까지만 확인했다. 실기에서는 틸트가 천천히 바뀔 때 영상 속 USV 의 세로 위치가 유지되는지 본다. 안 따라가면 조절할 곳은 aim() 의 0.5 s 와 2° 다(지금은 코드 상수).

가정과 오차

  • 수면 높이 이륙. h 는 이륙 지점 기준이다. 수면보다 Δh 높은 곳(부두 등)에서 뜨면 실제 수면 위 높이는 h + Δh 다. 참 틸트는 −atan2(h + Δh, s) 인데 덜 숙이게 되어, USV 가 화면 아래로 간다.
  • 겨누는 점은 USV 의 GPS 안테나다. 원하는 곳(갑판 가운데 등)과는 선체 크기만큼 다를 수 있다. 카메라와 우리 GPS 사이 거리(수 cm)는 무시한다.
  • 평면 근사. offset_to_gps 는 작은 거리용 평면 근사이고, 거리·방위는 구면식이다. 수 km 안에서는 차이를 무시할 만하다.
  • 등속 외삽. USV 가 돌면 원호를 직선으로 민 만큼 틀린다. 옆 오차 ≈ ½·v·ω·τ² 이고, 2 m/s · 10°/s · τ = 1 s 에서 0.17 m 다. 코드의 ponytail: 주석대로, 급선회나 수 초 지연이 문제가 되면 칼만 필터로 바꾼다.
  • 헤딩과 진행 방향은 다르다. 대형은 USV 헤딩(선수 방향) 기준이고, 외삽은 좌표로 잰 진행 방향을 쓴다. 조류·바람으로 옆으로 밀리면 둘이 다르다. 대형이 선체 기준인 것은 의도한 것이다.
  • 시각은 받은 시각이다. NavSatFix 의 stamp 는 쓰지 않는다. USV 쪽에서 생긴 지연은 lead_secs 가 대신 메운다(②).
  • 영상 되먹임이 없다. 위 표의 남는 오차를 줄이려면 영상에서 USV 를 찾아 틸트·기수를 보정하는 단계가 필요하다. 지금은 없다.
  • 좌표가 끊기면. USV 좌표가 lost_secs(2 s) 넘게 없으면 0 을 내며 제자리에 서고, 다시 오면 이어 간다. giveup_secs(10 s)를 넘기면 추종을 끝낸다. 우리 좌표가 1 s 끊기면 바로 끝낸다.

def plan(me, hdg, usv, usv_hdg, usv_vel, lead, form, p):    """한 tick 의 계산. ROS 없이 돈다.    me = (lat, lon, 상대고도) · usv = (lat, lon) · usv_vel = (북, 동) m/s · lead = 외삽 초    form = 대형 (앞, 오른쪽, 고도) — USV 기수 기준.    돌려주는 것: 추정 USV 좌표, 목표 좌표, 목표까지 m, USV 까지 수평 m, 틸트 °,                 /cmd_vel (x=앞 · y=오른쪽 · z=위 m/s, wz=시계 rad/s).    """    lat, lon, alt = me    vn, ve = usv_vel    # ponytail: 등속 외삽 — 급선회나 수 초 지연이면 틀린다. 그때 칼만으로    est = mav.offset_to_gps(usv[0], usv[1], 0.0, vn * lead, ve * lead)    goal = mav.offset_to_gps(est[0], est[1], usv_hdg, form[0], form[1])    dist = mav.meters_between(lat, lon, goal[0], goal[1])    rel = math.radians(mav.relative_bearing(mav.bearing_between(lat, lon, goal[0], goal[1]), hdg))    speed = min(p("max_speed"), p("kp") * dist)    h = math.radians(hdg)    vx = speed * math.cos(rel) + vn * math.cos(h) + ve * math.sin(h)    vy = speed * math.sin(rel) - vn * math.sin(h) + ve * math.cos(h)    norm = math.hypot(vx, vy)    if norm > p("max_speed"):        vx, vy = vx * p("max_speed") / norm, vy * p("max_speed") / norm    vz = clamp(p("kp_alt") * (form[2] - alt), p("max_vz"))    yaw_err = mav.relative_bearing(mav.bearing_between(lat, lon, est[0], est[1]), hdg)    wz = math.radians(clamp(p("kp_yaw") * yaw_err, p("max_yaw_rate")))    horiz = mav.meters_between(lat, lon, est[0], est[1])    tilt = max(-90.0, min(0.0, -math.degrees(math.atan2(max(alt, 0.0), horiz))))    return est, goal, dist, horiz, tilt, (vx, vy, vz, wz)

연습 문제

손으로 풀고 펼쳐서 확인한다. 마지막 둘은 노트북에서 직접 돌린다.

1. 우리 고도 6 m, USV 까지 수평 8 m 다. 틸트와 PWM 은?

풀이

θ = −atan2(6, 8) = −36.9°, PWM = 1500 + 5.5 × (−36.9) = 1297.2.

2. USV 헤딩 180°(남향), 대형 (−10, 0) 이다. 목표점은 USV 에서 어느 쪽인가?

풀이

N = −10·cos180° − 0 = +10, E = −10·sin180° = 0 → 북쪽 10 m. 남쪽을 보는 USV 의 뒤는 북이다.

3. 우리 기수 90°(동), USV 는 북쪽으로 1 m/s 간다. feedforward 의 (앞, 오른쪽)은?

풀이

앞 = 1·cos90° + 0 = 0, 오른쪽 = −1·sin90° + 0 = −1 → 왼쪽 1 m/s. 동쪽을 보는 기체에서 북은 왼쪽이다.

4. feedforward 없이 P 만으로 1.5 m/s 인 USV 를 따라가면 몇 m 뒤처지나?

풀이

e = v / kp = 1.5 / 0.35 = 4.3 m.

5. 고도 10 m 에서 USV 바로 위에 있다가 수평으로 1 m 벗어났다. 틸트는 몇 도 바뀌나?

풀이

−atan2(10, 1) = −84.3° → 5.7°. 바로 위에서의 감도 1/h = 0.1 rad/m = 5.73°/m 와 같다. 머리 위를 지날 때 짐벌이 가장 바쁘다.
