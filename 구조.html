데이터가 어디로 흐르나

포트는 둘이다. 14550 은 텔레메트리와 명령이 오가는 양방향 길, 5600 은 영상이 들어오는 한 방향 길.

토픽

주기는 앱이 보내는 주기 그대로다. python3 tools/topic_check.py 가 이 표를 기준으로 판정한다.

토픽타입주기내용
다운링크 — link_node 가 낸다
/rd/fixNavSatFix5 Hz위경도 + 상대고도(이륙 지점 기준)
/rd/rel_altFloat325 Hz상대고도 m
/rd/velocityTwistStamped5 Hz대지 속도 m/s, 동·북·위(ENU)
/rd/attitudeVector3Stamped10 Hzroll · pitch · yaw, 단위 도(°)
/rd/headingFloat6410 Hz기수 ° (0=북, 시계방향)
/rd/gspeedFloat3210 Hz대지속도 크기 m/s
/rd/batteryBatteryState1 Hz전압 · 전류 (patches/03 필요)
영상 — video_node 가 낸다
/image_rawImage~32 fps1632×1088
명령·항법 — 들어가는 것
/cmd_velTwist20 Hzlink_node 가 받아 #84 로. ROS 는 y=왼쪽이라 vy·회전 부호를 뒤집는다
/nav/goalNavSatFix한 번목표 좌표 (altitude = 상대고도)
/nav/cancelEmpty한 번중단
/nav/status · /nav/distanceString · Float32—nav_node 상태 · 목표까지 거리

현장에서 켜는 순서

앞 단계가 안 되면 다음 단계의 결과를 믿을 수 없다. 1~4 는 전부 14550/5600 을 직접 잡으니 하나씩 켜고 끈다.

  1. ./tools/link_check.sh이 PC 의 IP · 포트 점유 · 방화벽. 앱에 넣을 GCS IP 를 찍어 준다 (핫스팟 IP 는 매번 바뀐다)
  2. python3 tools/decode_check.py다운링크 — 좌표 · 위성 수 · 배터리 전압이 실제 값인지
  3. python3 tools/rd_cmd.py ping업링크 — 기체를 움직이지 않고 명령이 앱에 닿는지. 짐벌은 gimbal, 방향키 조종은 drive
  4. ./tools/video_view.sh영상을 창으로 본다. 안 나오면 video_probe.py 가 어디서 끊겼는지 짚는다
  5. python3 tools/gps_capture.py목표 지점 좌표를 잰다 (RC 로 그 자리까지 가서 Enter)
  6. ros2 launch rd_bridge bridge.launch.py nav:=false → python3 tools/topic_check.py브리지를 띄우고 토픽이 기대 주기로 차는지 판정표로 본다. 그다음 nav:=true 로 /nav/goal
기체 없이 할 수 있는 것 — 배관 확인까지만 tools/fake_app.py 앱 대역 (rd_cmd · link_node 를 붙여 본다) · video_node -p source:=저장한.h264 저장 영상으로 /image_raw · video_probe.py --save 진짜 스트림 받아 두기

절대 잊지 말 것

조종권은 저절로 RC 로 안 돌아온다 속도 명령을 한 발이라도 보내면 물리 스틱이 무시된다. 스틱을 잡아도, 도구를 꺼도 안 풀린다. 9/11 실기에서 통한 것은 S 모드 전환. 소스상 경로(도구 종료 → 스틱 놓고 5초 → 앱 Safety 버튼)는 아직 실기 확인 전.
UDP 14550 은 한 번에 한 프로그램만 link_node · QGC · tools 도구를 동시에 켜면 조용히 반씩 망가진다. 켜기 전에 link_check.sh 로 점유 확인.
ACCEPTED 는 성공이 아니고, 기체 없는 결과는 배관 확인일 뿐 앱은 DJI 가 에러를 내도 ACCEPTED 를 보낸다. 짐벌은 눈으로, 이동은 좌표 변화로 판정한다.
